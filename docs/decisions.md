# Decisions log

Format: `YYYY-MM-DD: decision — reason`. Append only; reversals get a new entry that references the old one.

2026-10-03: Pin n8n to `n8nio/n8n:2.41.6` — latest stable at P0; satisfies the ≥ 2.20.0 requirement for instance-level MCP (`N8N_MCP_ACCESS_ENABLED`).
2026-10-03: Pin Postgres to `postgres:17.11-alpine3.23` — 18.x changes the data directory layout/volume path; 17 is stable and supported by n8n, nothing here needs 18.
2026-10-03: One login role per database (`n8n` owns db `n8n`, `ops_app` owns db `ops`), created by `db/init/` on first start — n8n's Postgres credential for app data can't touch n8n internals, and vice versa.
2026-10-03: Migrations run by a one-shot `migrate` compose service (plain `psql` + `schema_migrations` table with sha256 checksums); n8n waits for it to exit 0 — no extra tool (Flyway/sqitch) for a handful of SQL files; edited-after-apply migrations abort loudly.
2026-10-03: Migration 001 contains only `audit_log` (append-only via triggers); domain tables land in the phase that first uses them (suppliers/POs/receiving in P1, invoices in P2, reconciliations in P3) — avoids locking in an invoice schema before the idempotency vs. duplicate-detection semantics are settled.
2026-10-03: Exported workflow files are named by slugified workflow name, and export strips `pinData`, `staticData` and volatile metadata (timestamps, version ids, sharing) — readable filenames, no execution payloads in git, and a re-export of unchanged workflows is byte-identical (enforced in CI).
2026-10-03: Workflow ids are preserved in exports — import updates in place, so `import.sh` is idempotent.
2026-10-03: gitleaks runs from the pinned `zricethezav/gitleaks:v8.30.1` image rather than gitleaks-action — same binary locally and in CI, no licence key.
2026-10-03: Host ports bind to 127.0.0.1; Postgres defaults to host port 5433 and Ollama to 11435 — dev machine already runs Postgres on 5432 and may run a native Ollama on 11434.
2026-10-03: `description_mismatch` is a labelled *condition*, not a flag reason — a line worded differently from the PO is what fuzzy matching is for; if item, quantity and price match, the right outcome is `recommend_approve`. Ground truth records the true PO-line mapping so P3 can score the matcher directly.
2026-10-03: `unknown_po` and `missing_po` are flag reason codes (expected `flag`), not `needs_review` — they are clear rule failures with a reason a human can act on; `needs_review` stays for extraction/matching we can't trust.
2026-10-03: Price tolerance 2% (unit price above PO); GST tolerance `ceil(taxable_lines / 2)` cents against 10% of the taxable subtotal, using the PO's GST status — per-line rounding is legitimate, and the invoice's own GST markers can be wrong. P3 must use the same values or explain why not.
2026-10-03: Invoice key is `sha256(abn_digits | UPPER(TRIM(invoice_number)) | total_cents)` with `|` separators — plain concatenation lets ("INV1", 23) collide with ("INV12", 3).
2026-10-03: Duplicates are generated as different files with the same key (half visibly stamped, half differing only in PDF metadata); byte-identical re-sends are a separate case with expected ingestion `noop`. Proposal for P2, not yet decided: skip on identical file hash, flag `duplicate_invoice` on same key with a different file.
2026-10-03: Generated data is not committed; output is deterministic (reportlab invariant mode) and the gate report is committed at `docs/synthetic-data-report.md`, with a test that fails if it goes stale.
2026-10-03: `seed.sql` records a fingerprint of the master data and refuses to load over data from a different seed or generator version — with ON CONFLICT DO NOTHING, same-numbered POs would otherwise silently keep stale lines.
2026-10-03: GST treatment follows broad Australian rules (fresh food GST-free; alcohol, chemicals, amenities, services, snacks taxable), simplified for a demo — it gives mixed GST invoices, which is what makes the GST check worth having.
2026-10-06: P2 ingestion trigger is an upload webhook — the eval harness calls the same endpoint as the demo, so the measured path and the shown path are identical. A watched folder or IMAP mailbox can sit in front of it later.
2026-10-06: P2 evaluates Ollama only (local, RTX 4060); the Anthropic comparison is out of P2 scope — no API key or spend for now. Revisit at the P2 gate if the local model misses the targets. CLAUDE.md's open decision on provider stays open until then.
2026-10-06: P2 accuracy targets confirmed — total, invoice number and PO number >= 98% exact match; line items >= 90% (a line counts only if description, quantity, unit price and line total all match).
2026-10-06: Duplicate handling supersedes CLAUDE.md principle 4's single key — idempotency is by file sha256 (identical bytes are a no-op); the same sha256(abn|invoice_number|total_cents) key with a different file is stored with `duplicate_of` set and flagged `duplicate_invoice` in P3. Keying on invoice_key alone would silently drop duplicates and make that flag unreachable.
2026-10-06: Ingestion is two tables — `invoice_files` (one row per file hash, including needs_review failures and the raw model output) and `invoices`/`invoice_lines` (validated extractions only) — failures have no valid data for typed columns, and a file that failed review must not be silently retried on re-upload.
2026-10-06: invoice_key is computed by Postgres (`invoice_key_of()`, a generated column), not in the workflow — one definition, checked against data-gen's Python version in tests and CI. IMMUTABLE is asserted by hand since convert_to() is only STABLE; the ops database is UTF8.
2026-10-06: The LLM transcribes, code calculates — the extraction schema returns money as dollar strings exactly as printed (`"1430.74"`), not cents or floats; conversion to cents, ABN normalisation and calendar-date validation are done in code. The model is told not to recalculate or correct totals, so a miscalculated GST on the invoice is extracted faithfully and caught by deterministic reconciliation.
2026-10-06: Extraction schema omits supplier address, email and phone (reconciliation never uses them; they'd only add noise to the accuracy numbers). Ground truth still carries them.
2026-10-06: Ground truth `document.lines[].unit` is null where the template prints no unit (till-receipt template C prints one only for kg) — an extractor can't be scored against a value that isn't on the page. `labels.lines` is unaffected. Similarly the generator never lets a taxable line print GST 0.00 on per-line-GST invoices.
